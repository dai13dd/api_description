05 / Code Example

実装イメージ：サーバー設定なし、関数を書くだけ

lambda_function.py 
import json
from typing import Any

def lambda_handler(event: dict[str, Any], context: Any) -> dict[str, Any]:
    # クエリパラメータを取得（例: GET /hello?name=DevTeam）
    params = event.get("queryStringParameters") or {}
    name = params.get("name", "World")

    return {
        "statusCode": 200,
        "headers": {"Content-Type": "application/json"},
        "body": json.dumps({"message": f"Hello, {name}!"}, ensure_ascii=False),
    }

NginxやUvicornの起動設定は一切不要。既存の FastAPI アプリを動かしたい場合も mangum 1行で対応可能です。

Function.cs (.NET) 
using System.Text.Json;
using Amazon.Lambda.APIGatewayEvents;
using Amazon.Lambda.Core;

public class Function
{
    public APIGatewayProxyResponse FunctionHandler(
        APIGatewayProxyRequest request, ILambdaContext context)
    {
        var name = request.QueryStringParameters?.GetValueOrDefault("name") ?? "World";

        return new APIGatewayProxyResponse
        {
            StatusCode = 200,
            Headers = new Dictionary<string, string> { ["Content-Type"] = "application/json" },
            Body = JsonSerializer.Serialize(new { message = $"Hello, {name}!" })
        };
    }
}

C# の静的型付けや既存ライブラリをそのまま活用可能。ASP.NET Core の Minimal API をそのまま Lambda 化することもできます。

06 / Good to Know

押さえておけば問題ない 3 つの制約

仕組みの特徴をあらかじめ知っておくだけで、設計時のつまずきを防げます。

コールドスタート（初回起動時のわずかな遅延）

数百ms〜数秒

しばらくリクエストがない後の初回実行時のみ起動時間がかかります。通常の社内APIでは気にならないケースが多く、シビアな場合は Provisioned Concurrency や .NET Native AOT で緩和できます。

タイムアウト制限

API Gateway 最大29秒 / Lambda 最大15分

同期APIレスポンスは29秒以内に返す必要があります。時間がかかる集計やファイル変換などは、SQS等を使った非同期処理に分けるのが定石です。

ステートレス設計が基本

ローカル永続保存不可

実行コンテナは使い捨てのため、ローカルディスクやメモリにデータを残せません。永続化や状態共有は必ず S3 や DB を使います。

07 / Coexistence & Summary

使い分けの目安：EC2とサーバーレスの共存

Recommended

サーバーレス（Lambda + APIGW）向き

  • 単機能APIや独立したマイクロサービス
  • アクセスに波がある社内API・業務ツール
  • 素早く作って、その後の保守負荷を下げたいAPI
  • C# / Python 混在チームでの並行開発

Keep on EC2

現状の EC2 + FastAPI 向き

  • 29秒を超える重い同期処理
  • 24時間コンスタントに高トラフィックがあるAPI
  • WebSocketの常時接続やローカル状態保持が必要な処理
